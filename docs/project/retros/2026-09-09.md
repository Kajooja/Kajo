## Process retrospective

What worked: generic domain boundaries survived catalog, bootstrap and Shared extensions; forward-only corrections preserved deployed migration bytes; later tests separated source reconciliation, platform ownership, fresh installation and populated upgrades. The explicit Taste/Friend decision also prevents accidentally shipping only the older recommender shell.

What caused repeated work: successful partial proofs and still-open acceptance were mixed into long chronological handoffs; later phase renumbering left old close criteria elsewhere; squash-merged branches looked unmerged to ancestry-only checks; installation failure diagnostics hid all startup details. None of these is solved by another undirected full audit.

Concrete improvements:

1. Each work package states its one remaining exit gate and required evidence. On completion, record the result once and stop. Rerun a completed experiment only for a changed implementation or a concrete unresolved risk.
2. Keep one current next action in STATUS. Historical sprint entries and PRs preserve the timeline; avoid a documentation commit merely to record the previous documentation commit's SHA.
3. When scope/phase numbers change, update the active sprint, milestone and affected open issue bodies in the same delivery. Keep implementation, hosted deployment, device testing and owner acceptance separate.
4. Diagnose a failed CI step before retry. This audit adds fixed startup symptom labels without logging CLI credentials or adding automatic retries. The original CI #395 cause remains unknown.
5. At a scoped pause, publish useful completed work, list the remaining acceptance gate and stop. Do not start optional model research, an APK polling cycle or another planning rewrite.
