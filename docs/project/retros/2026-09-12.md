## Open findings in the correct work packets

1. **#228 / 14.1–14.2:** visible ranking cache/readiness is not fully session-bound
   in current source. Rapid A → B → A can reuse an old A run before refetch. The
   prepared reader must bind environment/actor/Profile/session/domain/mode/request
   and test rapid return, errors and late responses. This is a source-level risk,
   not a reproduced physical-device incident.
2. **#228 / continuation:** native first-page retry races do not cover concurrent
   16-window cap creation or populated pre-window receipt upgrades. Add these with
   atomic page delivery, immutable per-page evidence and page-aware replay before
   enabling continuation or activating the new reader.
3. **#182 / 14.3 catalog:** catalog-import expects JWT bypass and server-key checks,
   but config.toml has no catalog-import entry. Verify current provider semantics,
   declare the intended config and test rejected/authorized requests. Unpinned
   `npm:@supabase/supabase-js@2` Edge imports and absent Edge entrypoint checks also
   need a reproducible lock/config/validation packet; root checks currently cover
   mobile and Node normalizers, not the Edge entrypoints.
4. **#160 / MVP-OPS-005:** production build config is optional and absent config
   permits intentional demo/mock client behavior. Production builds must fail
   closed and reject privileged-key shapes before bundling, while explicit local
   demo/test use remains available. No committed privileged value was identified.
5. **#160/#184 / public-entry readiness:** password-auth assumes an object request
   body, distinguishes account-existence states and has no source-level throttle.
   Validate JSON/field shapes and intended enumeration/rate-limit policy. External
   gateway controls and hosted exploitability were not established by this review.

These issues are recorded in existing issue owners. They are not silently waived,
fixed by documentation, or grounds for unrelated production mutations now.
